# zhang-ferret-hyperscanning-R34DA061924-ingest

Data ingest codebase for the Zhang lab's ferret hyperscanning project, nested
under `labs/zhang/ferret-hyperscanning/` in the
[data-ingest-task-force](https://github.com/brain-bbqs/data-ingest-task-force)
repo (see the [top-level README](../../../README.md) for how labs are
organized). The lab directory is nested from the start because the dataset
title also names human recordings.

It converts simultaneous wireless electrophysiology recordings of ferret
dyads (SpikeGadgets Sprite32 headstages through Trodes) plus five-camera
behavior video into NWB files. One recording produces two NWB files, one per
animal, in the DANDI layout, with the session's videos carried unchanged as
external files. See `code/README.md` for the input layout, the mapping and
the target NWB structure, and `prompts/initial.md` for the intake and the
reviewed plan.

## Layout

```
labs/zhang/ferret-hyperscanning/
  code/                 Conversion code
    _zhang_ferret_hyperscanning_to_nwb.py   one .rec recording -> two per-subject NWB files
    batch_convert.py                        loops it over an incoming dandiset -- what dispatch drives
    config.yaml                             metadata consumed by the converter (PROVISIONAL values marked)
    session_log.csv                         the lab's session-log sheet, exported and normalized
    README.md                               conversion notes (mapping, output structure, naming)
  containers/           The pinned, reproducible runtime (zhang-ferret-hyperscanning.Dockerfile)
  envs/                 Loose environment declaration
  tests/                Golden-summary integration test + unit tests (see Tests below)
    example_raw/          synthetic recording (generated by generate_fixtures.py)
    expected_output/      golden structural summary of the converted output
  prompts/              AI agent prompts given for this conversion
  OPEN_QUESTIONS.md     Open questions, their status, and where each placeholder lives
  README.md             This file
```

(Repository-wide tooling, e.g. ruff config, lives in `pyproject.toml` at the
repo root.)

## What is provisional

The plan was signed off with several questions deferred. The output is
runnable but not final until they are answered. Every open question, its
status, and where its placeholder lives is tracked in
[`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md). The ones that most affect the
output:

- The uploaded `.rec` is assumed to hold both headstages' ephys, although by
  size it cannot ([Q1](OPEN_QUESTIONS.md#q1-does-the-uploaded-rec-contain-the-ephys)),
  and the channel split between the two animals is assumed
  ([Q8](OPEN_QUESTIONS.md#q8-channel-numbering-per-headstage)).
- Videos are not yet synchronized to the ephys and start at the recording
  start ([Q5](OPEN_QUESTIONS.md#q5-camera-and-ephys-clocks),
  [Q7](OPEN_QUESTIONS.md#q7-which-din-carries-the-camera-frame-trigger)).
- Subject and session metadata are placeholders
  ([Q9](OPEN_QUESTIONS.md#q9-subject-and-session-metadata)).

## The environment

The Python environment is declared in `envs/pyproject.toml`. The interpreter
version (3.13) is pinned by `containers/zhang-ferret-hyperscanning.Dockerfile`'s
base image and by the CI test job, not by a file in `envs/`. The converter's
dependencies (pynwb, neuroconv with its `spikegadgets` and `video` extras,
PyYAML, tqdm) are all Python packages. There are no system-level
dependencies: the OpenCV wheels NeuroConv reads videos with bundle their own
FFmpeg libraries. A `dev` extra adds PyAV, which only
`tests/generate_fixtures.py` needs to write the synthetic AVI fixtures.

`zarr` is bounded below 3 for now: hdmf-zarr 0.14.0 requires zarr 3, which
neuroconv 0.10.2 cannot import under. Drop the bound once a neuroconv
release does.

Otherwise the declaration is intentionally *not* pinned. The Dockerfile
resolves it fresh at build time and the resulting image (by digest) is the
reproducibility lock, so there is no lockfile in the repository to keep in
sync. The image holds only the environment, not the code. The code and data
are mounted at run time, so a single image serves any revision of the
converter.

## Run it — with the container (reproducible)

Commands below assume the repository root as the working directory.

```bash
# Build locally...
docker build -t zhang-ferret-hyperscanning-ingest \
    -f labs/zhang/ferret-hyperscanning/containers/zhang-ferret-hyperscanning.Dockerfile \
    labs/zhang/ferret-hyperscanning

# ...or pull the image published by CI:
docker pull ghcr.io/brain-bbqs/zhang-ferret-hyperscanning-r34da061924-ingest:latest

# Mount the repo + data and run the converter on one recording
# (code is supplied at run time):
docker run --rm -v "$PWD":/work -w /work \
    ghcr.io/brain-bbqs/zhang-ferret-hyperscanning-r34da061924-ingest:latest \
    python labs/zhang/ferret-hyperscanning/code/_zhang_ferret_hyperscanning_to_nwb.py \
        --input path/to/incoming/000480/sourcedata/raw/Ferret_Hyperscanning/0236-0237/04.01.2026/0236HS3_0237HS4_20260401_130419.rec \
        --output path/to/standardized/000547 \
        --config labs/zhang/ferret-hyperscanning/code/config.yaml

# ...or run the batch driver over a whole incoming dandiset (what dispatch does):
docker run --rm -v "$PWD":/work -w /work \
    ghcr.io/brain-bbqs/zhang-ferret-hyperscanning-r34da061924-ingest:latest \
    python labs/zhang/ferret-hyperscanning/code/batch_convert.py \
        --input path/to/incoming/000480 --output path/to/standardized/000547 \
        --config labs/zhang/ferret-hyperscanning/code/config.yaml

# The same image runs the test suite:
docker run --rm -v "$PWD":/work -w /work \
    ghcr.io/brain-bbqs/zhang-ferret-hyperscanning-r34da061924-ingest:latest \
    python -m pytest labs/zhang/ferret-hyperscanning/tests/ -q
```

## Run it — locally (without the container)

Requires Python ≥ 3.10. From the repository root:

```bash
pip install "./labs/zhang/ferret-hyperscanning/envs"
python3 labs/zhang/ferret-hyperscanning/code/batch_convert.py \
    --input path/to/incoming/000480 --output path/to/standardized/000547 \
    --config labs/zhang/ferret-hyperscanning/code/config.yaml
```

## Tests

`tests/example_raw/` is a synthetic recording: a small Trodes file with two
32-channel headstages and a frame pulse on a digital input, ten tiny AVI
files named like the lab's, and a stray file the converter must report. It
is generated, not lab data, by `tests/generate_fixtures.py`, which also
writes `tests/expected_output/summary.json`, a structural summary of the two
NWB files and the placed videos (NWB writes HDF5, which is not byte-stable
across library versions, so the golden fixture is the summary rather than
the files). `test_conversion.py` runs the batch driver over the fixture and
compares, then checks that a second pass skips the converted recording.
`test_batch_convert.py` covers the identity rules, video matching,
session-log lookup, discovery and the skip/overwrite bookkeeping.

```bash
pip install "./labs/zhang/ferret-hyperscanning/envs[test]"
python -m pytest labs/zhang/ferret-hyperscanning/tests/ -q
```

Regenerate both fixtures after an intentional behavior change with
`python3 labs/zhang/ferret-hyperscanning/tests/generate_fixtures.py`.
