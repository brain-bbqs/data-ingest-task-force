# sanes-R34DA059513-ingest

Data ingest codebase for the Sanes lab, nested under `labs/sanes/` in the
[data-ingest-task-force](https://github.com/brain-bbqs/data-ingest-task-force)
repo (see the [top-level README](../../README.md) for how labs are organized).

It converts multi-animal gerbil vocal-interaction recordings into NWB files. The shared converter reads
continuous `idx_*` recording chunks and manifest-backed audio/video segments in
`concatenated_data_cam_mic_sync/`. BIG_ARENA_2024_12 uses the latter layout, with eight microphones and five
simultaneous cameras. Its grant is U01DA063581, its PI is Dan Sanes, and its institution is NYU.

|---|---|---|---|---|---|
| R34 | `sanes` | `000522` | `000523` | `code/config.yaml` | audio, video, SLEAP `.slp`, annotations |
| SSA GT | `sanes/ssa-gt` | `000524` | `000606` | `code/config_ssa_gt.yaml` | audio, video, SLEAP CSV `.tracks.csv`, annotations, experiment log |
| BIG_ARENA_2024_12 | `sanes/big-arena-2024-12` | `000601` | `000629` | `code/config_big_arena_2024_12.yaml` | eight-channel WAV audio, five MP4 cameras, sync manifest |

## What an idx-based session produces

```text
<standardized>/[autogenerated/]
  sub-multi/
    sub-multi_ses-<session>_behavior.nwb
    sub-multi_ses-<session>_video.mp4
  sub-<id>/
    sub-<id>_ses-<session>.nwb          one per tracked animal
```

`<session>` is the session folder's name with non-alphanumerics removed (`experiment_280` becomes
`experiment280`). The R34 config nests everything under `autogenerated/`, because `000523` already holds
earlier, hand-made work at its root. The other datasets write directly at the dandiset root.

| Source | Output |
|---|---|
| `idx_*/*.wav`, one per channel, concatenated across chunks | multisubject `acquisition/Multi-channel Acoustic Data` (`ndx_sound.AcousticWaveformSeries`) |
| `idx_*/*.mp4`, concatenated with FFmpeg | `sub-multi_ses-<session>_video.mp4`, an external `ImageSeries` in the multisubject file and in each track file |
| `idx_*/*.slp` or `idx_*/*.tracks.csv`, split by track | one `sub-<id>/` file per track holding its `Subject` and an `ndx_pose.PoseEstimation` with every landmark and its confidence |
| tracks, as subjects | multisubject `ndx_multisubjects.SubjectsTable`, one row per track, linked to its file by relative path |
| `idx_*/*annotations.csv` | multisubject `processing/behavior/vocalizations` (`pynwb.event.EventsTable` with `duration`, `label`, `channel`) |
| `*log_*.txt` beside the chunks | `session_start_time` (see below), and every log entry as the multisubject `notes` |
| `ssa_gt_experiment_metadata.yaml` (SSA GT only) | `session_description` for the experiment's range |

Audio and video must be present in every chunk of a session or in none. Pose and annotations may be missing
from any chunk. Chunk frame rates may differ by up to 0.1%, since containers round the same camera rate
differently (30 vs 1000000/33333).

The session start is the log's `Started Experiment Now` entry. Without one, it is the first free-text start
note (`exp start`, `started exp`, `Experiment Started`, and so on, but not `Restarted`). Without either, it is
the timestamp in the log's file name, which is when the logging program opened. Most SSA GT logs hold only
their header line, so they use the file name.

A session with neither audio nor video, pose without video, or no log and no configured
`session.start_time` fails with a clear error, and the batch moves on to the next session.

Annotations are placed on the concatenated audio clock (cumulative chunk audio duration), or on the video
clock when a session has no audio. Pose `frame_idx` values are placed on the concatenated video clock
(cumulative chunk frame count over the frame rate read from the video), the same clock the combined
`ImageSeries` uses. Before writing, NeuroConv's HDF5 backend configuration applies gzip level 4 compression.

## BIG_ARENA_2024_12

The requester approved the [conversion plan](prompts/big-arena-2024-12-plan.md) in Request 4 of the
[prompt record](prompts/big-arena-2024-12.md), which also holds the request, the metadata answers, and the
reviewer's decisions on the changes since approval. The supplied display name was `Big_Arean_2024_12`. The
existing machine key stays `sanes/big-arena-2024-12`. The source mapping and output outline are also in
[the code README](code/README.md#manifest-backed-audiovideo).

One experiment produces one `NdxMultiSubjectsNWBFile` plus five externally referenced, concatenated MP4s.
The eight mono microphone WAVs are stacked as the columns of one `ndx-sound` series, as in the other Sanes
datasets. No per-animal NWBs, pose, or vocalizations are synthesized.
`sync.csv` supplies the timestamp intervals and media associations. `README.txt` is cross-checked and both
texts are preserved inside the NWB.

`America/New_York` is a provisional timezone based on the requester's NYU/East Coast answer. Animal data is
not yet available. The converter reports an absent roster and omits the subjects table rather than
inventing animals. Add actual animals under `session_subjects.<experiment_name>` in the dataset config
when supplied. A real roster produces `SubjectsTable` rows without per-animal file links, verified by
round-trip tests.

The NWB file is blocked from upload by missing metadata and the lack of multisubject validation support.
Under dispatch's default `upload_validation: require`, the five MP4s would still publish without it, and
dispatch would then fail this project on every run until the NWB validates. Keep the entry off the runner
until then.

```bash
python3 labs/sanes/code/batch_convert.py \
  --input /path/to/000601/sourcedata/raw \
  --output /path/to/000629 \
  --config labs/sanes/code/config_big_arena_2024_12.yaml
```

BIG_ARENA_2025_03 (`000602`) has not been inspected (Q6). The requester expects it to share this layout,
so its config carries the same provisional timezone. Real WAV and MP4 assets of either dataset have not
been inspected or converted.

## Provenance

The lab's v1 notebook (`sanesDatatoNWB_v2.ipynb`) was ported first and is retired from the tree (git history
keeps it). The lab then supplied the v2 scripts, which are committed byte-for-byte apart from a short
provenance comment. They and `pynaViz_ex.py` are excluded from the formatters and linters, and none of them
run on their own, since they import a `utils.config` module the lab did not supply.

`_sanes_to_nwb.py` started as a function-by-function transcription of the v2 scripts. It is now the shared
converter for every Sanes dataset, built from the SSA GT conversion with the R34 inputs folded in. Compared
with the v2 scripts it:

- applies the gzip backend configuration that `sanes_multisubject_to_nwb.py` computed but never applied,
- references only the concatenated video, rather than each chunk video in the incoming tree, which fails
  DANDI upload validation,
- writes pose with `ndx-pose` on the concatenated video clock instead of through `sleap_io`'s NWB writer,
  which stored frame indices as timestamps and restarted them in every chunk,
- reads the frame rate from the video instead of assuming 30 fps,
- reads the session start from the experiment log when there is one, and keeps the log's notes,
- stores vocalizations as an `EventsTable` instead of `TimeIntervals`, as the SSA GT requester asked,
- stages audio in a disk-backed array instead of concatenating it in memory,
- writes the DANDI `sub-<id>/sub-<id>_ses-<session>` layout, and gives every file a session-unique identifier.

`sanes_individual_subject_to_nwb.py` is provenance only. It tries to attach a `Subject` to an exported
per-track NWB by guessing the track from a processing-module name, and as written only ever opens the last
file it finds. The converter writes the `Subject` into each track file when it creates it.

## Known rough edges

- Every dataset config is `PROVISIONAL`. The R34 subject overrides are the lab's own placeholder values.
- R34 sessions without an experiment log all get the one configured `session.start_time`.
- Subject ids come from sorted track order (or the R34 overrides), so the same id names different animals in
  different sessions (Q8).
- Pose and annotations sit on different clocks (video and audio). They agree only as far as each chunk's
  video and audio durations agree.
- Moving R34 onto this converter changed its output from `autogenerated/ses-<session>/...` to
  `autogenerated/sub-*/...`. The old files in `000523` are not removed by dispatch and need deleting by hand.
- R34 output is nested under `autogenerated/`, so DANDI reports `NON_DANDI_FOLDERNAME` and its dispatch entry
  uploads with `upload_validation: ignore` ([issue #20](https://github.com/brain-bbqs/data-ingest-task-force/issues/20)).
- `dandi validate` also reports `check_subject_exists` on every multisubject file, since `ndx-multisubjects`
  replaces `Subject` with `SubjectsTable`. It reports two upstream tooling errors too: pynwb's validator looks
  up `NdxMultiSubjectsNWBFile` in the `ndx-sound` namespace, and nwbinspector's
  `check_image_series_external_file_valid` crashes on the `NWBFile` subclass.

## The environment

The Python environment is declared in `envs/pyproject.toml`, unpinned apart from the bounds it explains
(`pynwb>=4` for `EventsTable`, `ndx-sound>=0.3.0` for multi-channel series, `zarr<3` for NeuroConv). `containers/sanes.Dockerfile`
resolves it at build time and adds FFmpeg, whose `ffprobe` and `ffmpeg` the converter shells out to. The
image digest is the reproducibility lock. The interpreter version (3.13) is pinned by the Dockerfile base
image and the CI job. `envs/original/` holds the v1 notebook's conda exports as a record, not a build input.

## Run it with the container

From the repository root:

```bash
docker run --rm -v "$PWD":/work -w /work \
    ghcr.io/brain-bbqs/sanes-r34da059513-ingest:latest \
    python labs/sanes/code/batch_convert.py \
        --input path/to/000524/sourcedata/raw/ssa_gt_data --output path/to/000606 \
        --config labs/sanes/code/config_ssa_gt.yaml
```

Swap the input, output, and config for another dataset (see the table at the top, or
`dispatch/projects.json`). The same image runs the test suite:

```bash
docker run --rm -v "$PWD":/work -w /work \
    ghcr.io/brain-bbqs/sanes-r34da059513-ingest:latest \
    python -m pytest labs/sanes/tests/ -q
```

## Tests

`tests/synthetic.py` writes idx-based sessions in the source layout the lab described, with any mix of data
types: two chunks of per-channel WAVs, tiny MP4s, pose as `.slp` or `.tracks.csv`, annotations, and an
optional log. Those are generated at test time. The manifest session under `tests/example_raw/big_arena/` is
committed instead: six one-second segments, eight microphones with distinctive samples, and five cameras
with distinct colors and segment marks. Both are synthetic, not lab recordings.

`test_converter.py` converts an SSA GT-style and an R34-style session end to end and checks the files read
back with PyNWB, plus an audio-only session and every unconvertible mix. For the manifest session it checks
the golden summary in `tests/expected_output/big_arena.json`, then pins timing, provenance, devices, and
validation explicitly, since the summary is only a snapshot of the converter's own output. It also covers
every rejected source, segment lengths against `sync.tolerance`, 29.97 fps cameras with embedded audio,
timecode tracks, in-file start offsets, symlinked media, and the roster rules. `test_batch_convert.py` covers
discovery, skip and overwrite, pending and failed results, and failure handling with the converter stubbed.
FFmpeg with `libx264` and `aac` must be on `PATH`.

```bash
pip install "./labs/sanes/envs[test]"
python -m pytest labs/sanes/tests/ -q
```

Regenerate the manifest fixture and its summary with `python3 -m labs.sanes.tests.generate_fixtures`.
