# suthana-in-lab-R61MH135106-ingest

Data ingest codebase for the Suthana lab's **in-lab** project, nested under
`labs/suthana/in-lab/` in the
[data-ingest-task-force](https://github.com/brain-bbqs/data-ingest-task-force)
repo (see the [top-level README](../../../README.md) for how labs are
organized).

It converts aligned MATLAB recordings of an indoor navigation task into NWB
files, combining intracranial EEG, 63-channel scalp EEG, motion-capture body
tracking, head rotation, eye tracking, and the beep/button behavioral events.
One `.mat` file is one subject's whole experiment, split into several
non-contiguous recording segments, and becomes one NWB file. See
`code/README.md` for the input data layout and the target NWB structure.

The conversion scripts were originally authored by Neha Thomas and are ported
here. See [Deviations from the original](#deviations-from-the-original) for
what changed on the way in and why.

## Layout

```
labs/suthana/in-lab/
  code/                          Conversion code, ported from the original work
    _suthana_in_lab_to_nwb.py      one subject .mat -> one NWB file (private core module)
    batch_convert.py               batch driver: every .mat under a directory -> NWB tree
    config.yaml                    metadata template consumed by the converter
    README.md                      the original conversion notes + the input data layout
  containers/                    The pinned, reproducible runtime (suthana-in-lab.Dockerfile)
  envs/                          Loose environment declaration + pinned Python version
  tests/                         Two suites + a committed mock .mat fixture
    example_raw/                   mock raw input (generated by generate_fixtures.py)
    config.yaml                    filled-in metadata the tests convert with
  prompts/                       AI agent prompts given for this conversion
  README.md                      This file
```

(Repository-wide tooling, e.g. ruff config, lives in `pyproject.toml` at the
repo root.)

## Why the project sits under a lab folder

This is the first lab in the repository contributing more than one project, so
its code lives at `labs/<lab>/<project>/` rather than `labs/<lab>/`. Dispatch
registers it as lab `suthana`, project `in-lab`, which makes its key
`suthana/in-lab` in `dispatch/sessions.json` and in `dispatch.py --only`. A
future second Suthana project becomes a sibling directory, and labs with a
single project keep their current flat layout unchanged. See
`dispatch/README.md` for the field reference.

## The metadata config

Everything the original script hardcoded lives in `code/config.yaml` instead:
session and device descriptions, the subject table (raw id, de-identified paper
id, age, sex, iEEG channel localization), the 63-channel scalp montage, and the
de-identification settings.

Two values still need the lab's confirmation, marked `PROVISIONAL` in the file:

- **Institution.** The original writes `Duke University`. The Suthana lab is at
  UCLA and the recordings are timestamped `America/Los_Angeles`, so this looks
  like a copy/paste from another conversion. It is kept as the original wrote
  it rather than silently corrected. Confirm before treating the standardized
  output as final.

## Deviations from the original

The port is not verbatim. `code/` was reformatted and lint-fixed to the
repository's style, the hardcoded paths and metadata were lifted into
`config.yaml` and CLI flags, and the batch loop became `batch_convert.py` so
dispatch can drive it over a whole incoming dandiset.

Four behavioral changes go beyond that. Each fixes something in the original
that produced wrong output or would have crashed, and each is covered by a test
in `tests/test_conversion.py`:

- **The de-identification offset is now deterministic.** The original drew the
  date shift from an unseeded `random`, so every re-run invented new session
  start times for the same input. Dispatch re-runs the conversion whenever the
  script changes, which would have rewritten every session's timestamps each
  time. The offset is now derived from the configured seed and the subject id,
  so it is stable across runs while keeping the original's distribution
  (±365 days, ±12 hours) and leaving relative timing within a subject
  untouched. Set `deidentification.enabled: false` to write the real times.
- **The scalp EEG artifact mask stores the scalp EEG mask.** The original built
  `EEG Artifact Series` from `iEEG1bool`, the iEEG mask, so `ix_art` never
  reached the file and the stored mask had the wrong channel count.
- **The scalp EEG series reference their own electrode rows.** The original
  built the scalp table region as `range(63)`, which indexes rows 0-62 of a
  67-row electrode table: the four iEEG electrodes plus the first 59 scalp
  ones. It is now `range(4, 67)`.
- **Event tables are built once, from their own indices.** The original
  appended each beep chunk to `beep_events` twice, so every beep row was
  duplicated, and populated the button table's index column from the *beep*
  indices. It also declared the `DynamicTable` column as `Timestamp Index`
  while the dataframe column was `Index`, which raises on
  `DynamicTable.from_dataframe`.

Smaller cleanups along the way: the loop-carried `column_names` variable no
longer leaks the previous file's scalp labels into the next subject's electrode
table, unused counters were dropped, and event rows are sorted by time.

## The environment

The Python environment is declared in `envs/pyproject.toml`. The interpreter
version (3.13) is pinned by `containers/suthana-in-lab.Dockerfile`'s base
image and by the CI test job, not by a file in `envs/`. The converter's
dependencies (numpy, pandas, h5py, pynwb, hdmf, neuroconv, PyYAML, tqdm) are
all Python packages. There are no system-level dependencies: the raw `.mat`
files are MATLAB v7.3, which is HDF5, so h5py reads them without a MATLAB
runtime.

The declaration is intentionally *not* pinned.
`containers/suthana-in-lab.Dockerfile` resolves it fresh at build time and the
resulting image (by digest) is the reproducibility lock, so there is no
lockfile in the repository to keep in sync. The image holds only the
environment, not the code. The code and data are mounted at run time, so a
single image serves any revision of the converter.

## Run it — with the container (reproducible)

Commands below assume the repository root as the working directory.

```bash
# Build locally...
docker build -t suthana-in-lab-ingest \
    -f labs/suthana/in-lab/containers/suthana-in-lab.Dockerfile labs/suthana/in-lab

# ...or pull the image published by CI:
docker pull ghcr.io/brain-bbqs/suthana-in-lab-r61mh135106-ingest:latest

# Mount the repo + data and run the batch converter (code is supplied at run time):
docker run --rm -v "$PWD":/work -w /work \
    ghcr.io/brain-bbqs/suthana-in-lab-r61mh135106-ingest:latest \
    python labs/suthana/in-lab/code/batch_convert.py \
        --input 000530 --output 000531 --config labs/suthana/in-lab/code/config.yaml

# The same image runs the test suite:
docker run --rm -v "$PWD":/work -w /work \
    ghcr.io/brain-bbqs/suthana-in-lab-r61mh135106-ingest:latest \
    python -m pytest labs/suthana/in-lab/tests/ -q
```

## Run it — locally (without the container)

Requires Python ≥ 3.10. From the repository root:

```bash
pip install "./labs/suthana/in-lab/envs"

# One subject:
python3 labs/suthana/in-lab/code/_suthana_in_lab_to_nwb.py \
    --mat path/to/R056_aligned_data.mat \
    --out path/to/out/sub-S1_ses-inlab_behavior+ecephys.nwb \
    --config labs/suthana/in-lab/code/config.yaml

# A whole incoming dandiset:
python3 labs/suthana/in-lab/code/batch_convert.py \
    --input path/to/000530 --output path/to/000531 \
    --config labs/suthana/in-lab/code/config.yaml
```

`_suthana_in_lab_to_nwb.py` handles one subject per invocation, taking the
segment start times from a `Trajectories_runtimes.csv` beside the `.mat` file
unless `--runtimes` points elsewhere. `batch_convert.py` wraps it for the whole
incoming dandiset: it converts every `.mat` file found under `--input`, resolves
each subject's de-identified label from the `Subject_ID` stored *inside* the
file (not from its filename, so a renamed upload still lands correctly), and
writes `sub-<paper id>/sub-<paper id>_ses-inlab_behavior+ecephys.nwb` under
`--output`. Subjects whose output already exists are skipped unless
`--overwrite` is passed. Subjects are converted in parallel, one worker process
per CPU by default, and `--jobs` sets that count explicitly. A tqdm bar reports
completions.

An incoming dandiset with no `.mat` files is not an error: the batch driver
reports that it found nothing and exits 0, so a dispatch pass over an empty
incoming dandiset succeeds and simply converts nothing.

## Tests

Two suites, both run against a committed mock recording
(`tests/example_raw/`, generated by `tests/generate_fixtures.py`) with the
filled-in `tests/config.yaml`:

- `test_conversion.py` runs the converter end to end, then reads the produced
  NWB file back and asserts its structure and contents match the fixture. NWB
  writes HDF5, which is not byte-stable across library versions, so the
  assertion is on the read-back contents rather than on golden bytes as in
  `labs/kemere/`. Each of the four behavioral fixes listed above has a test
  that fails against the original's behavior.
- `test_batch_convert.py` covers discovery, output naming, runtimes lookup,
  skip/overwrite, and the batch run itself.

The fixture is written with h5py rather than `scipy.io.savemat`, because the
real files are MATLAB v7.3 and the conversion depends on the object references
and UTF-16 char arrays that format uses. `generate_fixtures.py` reproduces both
encodings.

```bash
pip install "./labs/suthana/in-lab/envs[test]"
python -m pytest labs/suthana/in-lab/tests/ -q
```
